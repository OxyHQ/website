# Search indexing

How a URL on oxy.so gets into Google's index, and the four places this build can
stop it. Written against the Search Console "Page indexing" export of
2026-09-11, which reported 3,921 known URLs: 1,072 indexed and 2,849 not.

| Search Console reason | Pages | Cause in this repo |
| --- | ---: | --- |
| Page with redirect | 725 | Every internal link was slash-less, and Cloudflare 308s those. |
| Alternate page with proper canonical tag | 317 | Superseded docs versions were advertised in `sitemap.xml`. |
| Excluded by `noindex` | 291 | Stale URLs answered 200 with the SPA, which rendered `NotFoundPage`. |
| Duplicate without user-selected canonical | 26 | Unknown URLs served the home page document, canonical included. |
| Not found (404) | 24 | Retired URLs, plus eight dead links the synced Astro docs published. |
| Soft 404 | 8 | Same 200-for-everything fallback as the duplicates above. |
| Discovered – currently not indexed | 1,171 | ~4,200 locale mirrors of English-only API reference. |
| Crawled – currently not indexed | 263 | The same crawl budget, spent before reaching the real pages. |

## One URL shape, three signals, one helper

Cloudflare Pages serves `dist/<route>/index.html` at `<route>/` and answers the
bare `<route>` with a 308. So the canonical URL of every document on this site
ends in a slash, and `withDocumentTrailingSlash` in `src/lib/seoUrl.ts` is the
only thing that decides that — for the canonical tag, the hreflang set, the
sitemap, structured data, the RSS feed, and (since this change) links.

`src/lib/canonicalPath.ts` applies it to link targets, `src/lib/navigation.tsx`
wraps `Link`/`NavLink` with it, and `mdxComponentMap` / `ArticleMarkdown` apply
it to prose. Two guards keep it that way: a `no-restricted-imports` rule for the
react-router originals, and `scripts/internal-links.test.ts`, which also rejects
a hand-written `<a href="/…">` without the slash. Routes themselves stay
slash-agnostic — React Router matches either form.

## What answers a URL with no document

`dist/_redirects` is generated by `scripts/redirects.ts` during `postbuild`,
because its locale rules depend on which locales the prerender actually mirrored.
It ends in `/*  /404.html  404`. Before this change it ended in
`/*  /index.html  200`, and `dist/index.html` is the prerendered **home page**:
every misspelling and every retired URL answered 200 with a byte-exact copy of
the home page, carrying `<link rel="canonical" href="https://oxy.so/">`.

Two kinds of path escape the 404 in that file:

- **Retired URLs** — `/technologies`, `/products`, `/pay` 301 at the edge
  instead of 200-ing into a client-side `<Navigate>`.
- **Locale prefixes** — see below.

## What a `_redirects` rule actually beats

This cost a production outage, so it is worth stating precisely. Cloudflare
Pages does **not** simply serve a static asset ahead of `_redirects`:

| Rule | Asset exists at that path | Result |
| --- | --- | --- |
| `200` rewrite | yes | **the rule wins** — the asset is shadowed |
| `404` | yes | the asset wins |
| bare `/*` (any status) | yes | the asset wins |

The first release of this change used `200` rewrites for the SPA fallback
families — `/newsroom/*`, `/apps/*`, `/developers/docs/*` and so on. Every one
of them shadowed the documents underneath it: all fifteen prerendered Newsroom
posts, 2,087 docs pages, every job and app page, each answered with a 308 to
`/app-shell` (Pages' own `.html` stripping applied to the rewrite target).

So the SPA fallback moved to `functions/_middleware.ts`. `src/lib/spaFallback.ts`
holds the patterns; the middleware sees the 404 the catch-all produced and
upgrades it to the shell. A document always wins now, because by the time that
code runs Cloudflare has already looked for one and not found it. Neither
fallback document carries a static `<meta name="robots">` — Helmet only manages
tags it emits, so a baked-in `noindex` would survive React's mount forever.

**Never add a `200` rewrite to `_redirects` over a prefix that has documents.**
`scripts/seo-contract.test.ts` fails on any `200` rule in that file at all.

`scripts/routing-contract.test.ts` runs in `postbuild` and fails the build if a
route declared in `src/App.tsx` is neither prerendered, nor covered by a rule,
nor claimed by `isSpaFallbackPath` — so the 404 can never quietly swallow a real
page. `scripts/link-audit.ts` then
resolves every URL the build publishes — literal `to=`/`href=` in `src/`, every
`<a href>` in every prerendered document, and every `<loc>` and hreflang in the
sitemap — against `dist/`, and fails on anything that is not a 200. It is strict
by default, like the prerender; `LINK_AUDIT_STRICT=0` downgrades it to a report
for the case where the only finding came from upstream prose a docs sync pulled
in and a deploy should not wait on it.

## Locales

`src/lib/localizedRoute.ts` is the single authority for which routes have a
translated variant, read by `<SEO>` (hreflang), `scripts/sitemap.ts`
(`xhtml:link` alternates) and `scripts/prerender.ts` (which documents get
written). Today it excludes `/developers/docs/**`: that tree is synced from each
package's own English source, so `/es/developers/docs/bloom/1.0.0/use-theme/`
served a byte-identical copy of the English page. At 2,087 of 2,217 routes,
mirrored across two locales, that was ~4,200 duplicate URLs competing for the
crawl budget the real pages were waiting for.

Two more locale rules:

- **hreflang is reciprocal.** Every page in the set must list the whole set,
  itself included. The default locale is `translationReady: false` by
  construction, so it fell out of the filter and the set shipped without its own
  member — `x-default` is not a substitute, and a set missing its self-reference
  is dropped whole.
- **An unreachable `/api/locales` is not an answer.** The prerender reports `[]`
  both when no locale qualifies and when the fetch fails, so `_redirects` takes
  `localeReadinessKnown` separately. Reading a timeout as "no locale has pages"
  would 301 every live `/es/…` URL onto its English counterpart.

## Verifying a change here

`bun run build` covers it: `prebuild` runs the link and SEO-contract tests,
`postbuild` runs the routing contract and the link audit against the real
artifact. To check the parts that depend on the CMS (locale mirrors, newsroom
prose, jobs), point `VITE_API_URL` at a stub — the prerender reads it the same
way the SPA does.

Search Console is the slow half. Redirect and duplicate buckets drain as Google
re-crawls; "Discovered – currently not indexed" only moves once the crawl budget
stops going to URLs that were never worth crawling.

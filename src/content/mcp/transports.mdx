# Transports

The Oxy MCP server runs **one** transport: **stateless Streamable HTTP** at `https://website-api.oxy.so/mcp`. There is no stdio mode, no legacy HTTP+SSE pair and no WebSocket option. The server runs on Oxy's infrastructure and any number of clients connect to it over HTTPS.

## Stateless Streamable HTTP

[Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#streamable-http) carries JSON-RPC messages over HTTP. The Oxy server uses it without sessions:

- **Every request stands alone.** Each `POST /mcp` carries its own access token and is checked against Oxy on arrival. The server does not issue an `mcp-session-id`, so there is no session to lose when a request reaches a different server instance, and nothing to clean up.
- **Responses are plain JSON.** Each `POST` receives its JSON-RPC response in the HTTP response body.
- **Only `POST` carries messages.** `GET` and `DELETE` on `/mcp` answer `405 Method not allowed`: without sessions there is no server-to-client stream to open and no session to delete.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/mcp` | Send a JSON-RPC request (`initialize`, `tools/list`, `tools/call`, …) with `Authorization: Bearer <access token>` |
| `GET` | `/.well-known/oauth-protected-resource/mcp` | Protected resource metadata used to discover Oxy as the authorization server |

## Authentication on every request

Authentication happens before the message is read:

1. No `Authorization: Bearer` header → `401` with a `WWW-Authenticate` challenge pointing at the protected resource metadata.
2. The token is introspected with Oxy. An inactive, expired, revoked or wrongly scoped token → `401` with `error="invalid_token"`.
3. Oxy unreachable → `503`, `Authorization service unavailable.`

Tokens are only read from the `Authorization` header. See [Authentication](/developers/docs/mcp/authentication) for the sign-in flow.

## Clients

- **Claude on the web and Claude Desktop** connect through **Settings → Connectors → Add custom connector**.
- **Claude Code** connects with `claude mcp add --transport http`.
- **Custom clients** built with the official [TypeScript](https://github.com/modelcontextprotocol/typescript-sdk) or [Python](https://github.com/modelcontextprotocol/python-sdk) SDK use their Streamable HTTP client transport together with the SDK's OAuth support, which handles the `401` challenge, client registration with Oxy and the approval in the browser. Do not hard-code a bearer token: access tokens are short-lived and bound to the person who approved them.

See the [Quickstart](/developers/docs/mcp/quickstart) for the exact steps.

## What the server does **not** support

- **Sessions.** There is no `mcp-session-id`, no resumable stream and no server-initiated notification.
- **stdio.** The server cannot be spawned locally by a client.
- **HTTP+SSE (legacy).** The 2024-11-05 two-endpoint design (`POST /messages` plus `GET /sse`) is not provided. Clients that only speak it cannot connect.
- **WebSockets.** Not an MCP transport.
- **Anonymous requests.** Every request needs an Oxy access token, including reads of public content.

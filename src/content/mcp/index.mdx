# Oxy MCP Server

The Oxy MCP server exposes the content of [oxy.so](https://oxy.so) — newsroom, pages, jobs, team, products, Academy, Help Center, pricing, locales, media and more — as tools that any [Model Context Protocol](https://modelcontextprotocol.io) client can call: Claude on the web, Claude Desktop, Claude Code, or an agent built on an MCP SDK.

## At a glance

| | |
|---|---|
| Endpoint | `https://website-api.oxy.so/mcp` |
| Transport | Streamable HTTP, stateless |
| Sign-in | Oxy OAuth — you approve the connection on auth.oxy.so |
| Scopes | `website.read` for reads, `website.write` for writes |
| Metadata | `https://website-api.oxy.so/.well-known/oauth-protected-resource/mcp` |

There are no API tokens to create, copy or paste. Your MCP client discovers Oxy from the server's `401` challenge, sends you to auth.oxy.so to approve the connection, and from then on carries a short-lived token that Oxy issued for this server only.

## What you can do

Anyone with an Oxy account can connect and **read** public website content — the same content an anonymous visitor to oxy.so sees:

- "List the five most recent newsroom posts and summarise them."
- "Which open jobs are in engineering?"
- "Show me the Help Center articles in *Getting started*."

**Website admins** can also **write** — create, update and delete content — and use the reads that have no public equivalent (drafts, media library, translations, referrals, tracked repositories):

- "Draft a newsroom post titled *Oxy ships native federation* and keep it unpublished."
- "Translate the hero into Catalan."
- "Pause the referral code `BEN-2026`."

See [Authentication](/developers/docs/mcp/authentication) for exactly how access is decided.

## What it is, briefly

The [Model Context Protocol](https://modelcontextprotocol.io) is an open standard for letting language models call external tools. An MCP server advertises a list of tools; the client picks one, sends its arguments as JSON-RPC, and receives a result.

The Oxy MCP server runs inside the website's API. Every request is authenticated on its own and checked live against Oxy, so any instance of the API can answer any request and there is no session to keep alive.

It is **not** the Oxy platform API. `api.oxy.so` powers identity, files and billing for Oxy apps; this server only reads and manages the content of the oxy.so website.

## What it does not expose

- No **resources** (`resources/list`) and no **prompts** (`prompts/list`) — only tools.
- No anonymous access. Even reads require signing in with an Oxy account; they then return only public content.

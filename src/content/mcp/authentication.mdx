# Authentication

The Oxy MCP server uses **Oxy as its authorization server**. You connect by approving the client on auth.oxy.so; the client then sends a short-lived access token that Oxy issued for this server alone. The website never issues, stores or accepts tokens of its own.

## How sign-in works

1. **The client calls the server without a token.** `POST https://website-api.oxy.so/mcp` answers `401` with a `WWW-Authenticate` header that points at the protected resource metadata.
2. **The client reads the metadata** at `https://website-api.oxy.so/.well-known/oauth-protected-resource/mcp`. It names the resource and Oxy as the authorization server.
3. **The client registers itself with Oxy** and sends you to **auth.oxy.so**, where you sign in and approve the connection and the scopes it asks for.
4. **The client retries with the access token.** Tokens are short-lived and bound to this resource: a token issued for another Oxy MCP server is not accepted here.
5. **Every request is checked live.** The server asks Oxy about the token on each call, so a revoked connection stops working on its next request.

Tokens travel only in the `Authorization: Bearer` header. A token in a query string is never read.

## Scopes

| Scope | Grants |
|---|---|
| `website.read` | Read tools |
| `website.write` | Write tools — create, update, delete, upload and sync |

A scope is necessary but not sufficient: what a call may actually do also depends on the account behind the connection.

## The active account

Oxy lets one connection hold more than one account. Every call is judged on the connection's **active account** — the account Oxy reports for the token at that moment — never on another account the connection could switch to.

## Who can do what

| Active account | Reads | Writes |
|---|---|---|
| A website admin | Every read, including drafts and admin-only data | Every write |
| Any other Oxy account | Public reads only | None |

**Admins** are the accounts listed in the website's admin configuration. Everyone else gets reads answered by the site's own public API, requested with no credentials — exactly what an anonymous visitor to oxy.so receives, not a filtered copy of admin data. That means:

- **Admin-only reads.** Reads with no public equivalent are admin-only: drafts, the media library, pages listings, translations, referrals and tracked repositories.
- **Refused filters.** A filter the public API does not implement (for example, asking for drafts) is refused with an error rather than silently dropped, so a result never looks complete when it is not.
- **No writes.** Write tools return an error saying they are only available to website admins.

## Errors

Authentication problems are answered at the HTTP level, before any tool runs:

| Status | JSON-RPC code | Meaning |
|---|---|---|
| `401` | `-32001` | No token, or the token is inactive, expired, revoked or issued for another resource. The `WWW-Authenticate` header tells the client to sign in again. |
| `503` | `-32000` | Oxy could not be reached to check the token. Retry later. |

Once a tool runs, a failure comes back as a normal tool result with `isError: true`, a stable error code and a short message — for example, a tool that is only available to website admins, or a refused filter. Tool errors never include stack traces or internal details.

## Revoking access

Open your **Oxy account settings** and remove the connection. The next request from that client fails with `401` and the client asks you to sign in again. Removing the connector from the client also stops it from calling the server, but only revoking it in Oxy invalidates the access it was granted.

## Migration from static tokens

Earlier versions of this server used static API tokens that admins minted in the website (`create_mcp_token`, `revoke_mcp_token`), sent either as a bearer header or as `?token=` in the URL, at `https://api.oxy.so/mcp`, with token hashes stored in MongoDB. All of that has been removed: those tokens are no longer accepted and those tools no longer exist. To migrate, delete the old server entry and any stored token from your client, then add `https://website-api.oxy.so/mcp` following the [Quickstart](/developers/docs/mcp/quickstart).

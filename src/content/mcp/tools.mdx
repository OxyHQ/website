# Tools

The Oxy MCP server's tools are declared once in the server and published to Oxy as the website's capability catalog. Your MCP client receives the current list, with each tool's description and input schema, when it connects — that list is always the authoritative reference.

## Categories

Tools cover these areas of the website:

| Category | What it covers |
|---|---|
| Newsroom | Posts, search and cover images |
| Pages and site chrome | Marketing pages, hero, navigation and footer |
| Products and categories | The products and technologies catalog |
| Academy | Courses and resources |
| Help Center | Help articles |
| Careers and team | Jobs and team members |
| Pricing and testimonials | Pricing plans and testimonials |
| Changelog | Changelog entries and the GitHub repositories they sync from |
| Media | The media library and image uploads |
| Localization | Locales and translations |
| Settings | Site-wide settings |
| Referrals | Referral codes |

## Access classes

Every tool belongs to one of three classes:

| Class | Scope | Who can call it |
|---|---|---|
| Public read | `website.read` | Any Oxy account. Non-admins get the site's public data; admins get the full data. |
| Admin read | `website.read` | Website admins only — data with no public equivalent, such as drafts, media, translations, referrals and tracked repositories. |
| Write | `website.write` | Website admins only. |

A non-admin's public read is answered from the site's public API. A filter that API does not support is refused with an error rather than ignored. See [Authentication](/developers/docs/mcp/authentication) for the full rules.

## Inputs

Inputs are validated against each tool's schema before anything runs, so a call with the wrong shape is rejected without touching any data. Identifiers are 24-character hexadecimal `_id` strings.

## Results and errors

A successful call returns a text content block whose body is JSON.

A failed call returns a tool result with `isError: true`, a stable error code and a short, human-readable message — for example, a tool that is only available to website admins, a refused filter, or an item that was not found. Errors never contain stack traces or internal details, so they are safe to show to the person using the client.

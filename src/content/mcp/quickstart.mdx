# Quickstart

Connect an MCP client to `https://website-api.oxy.so/mcp` and approve the connection with your Oxy account. There is no token to create or paste: the client handles sign-in for you.

<Callout variant="info" title="You will need">
  - An **Oxy account**. Any account can read public content; writes need an account that is a website admin.
  - An MCP client that supports remote servers with OAuth sign-in — Claude on the web, Claude Desktop, Claude Code, or an MCP SDK client.
</Callout>

## 1. Add the server

### Claude (web and desktop)

1. Open **Settings → Connectors** and choose **Add custom connector**.
2. Enter the URL `https://website-api.oxy.so/mcp`. Leave any client ID and secret fields empty — the client registers itself automatically.
3. Select **Connect**. Claude opens auth.oxy.so; sign in if needed and approve the connection.

The connector then lists the tools your account can use.

### Claude Code

Register the server over HTTP, then sign in from inside a session:

```bash
claude mcp add --transport http oxy-website https://website-api.oxy.so/mcp
```

Run `/mcp` in Claude Code, select **oxy-website** and choose to authenticate. Your browser opens auth.oxy.so; approve the connection and return to the terminal.

### Any MCP client

Point a client that implements [MCP authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) at the endpoint. On the first request the server answers `401` with a `WWW-Authenticate` header naming its protected resource metadata:

```
WWW-Authenticate: Bearer realm="website-mcp", resource_metadata="https://website-api.oxy.so/.well-known/oauth-protected-resource/mcp"
```

The metadata names Oxy as the authorization server. The client registers itself with Oxy, sends the person through the approval on auth.oxy.so, and retries with the access token it receives. With the official SDKs this is handled by the transport's OAuth support; you do not set an `Authorization` header by hand.

## 2. Try your first call

Ask Claude:

> List the five most recent newsroom posts and show me their titles.

Claude calls the newsroom listing tool and renders the result. You should see the same posts that appear on the [oxy.so newsroom](https://oxy.so/newsroom/).

If your account is a website admin, try a write:

> Create a draft newsroom post titled "Hello from MCP". Do not publish it.

On any other account the same request is refused with a clear message: writes are admin-only.

## 3. If something goes wrong

| What you see | What it means | What to do |
|---|---|---|
| The client asks you to sign in again | Your access token expired or was revoked | Reconnect and approve again on auth.oxy.so |
| `Authorization service unavailable.` (HTTP `503`) | The server could not reach Oxy to check your token | Retry shortly; nothing is wrong with your connection |
| A tool result marked as an error saying the tool is only available to website admins | The connection's active account is not a website admin | Switch to an admin account, or use a read |
| A tool result marked as an error refusing a filter | The public read does not support that filter | Remove the filter, or use an admin account |

See [Authentication](/developers/docs/mcp/authentication) for how access is decided and how to revoke a connection.
